# Weaver Plugin API Reference

Welcome to the Weaver Plugin Developer Guide. Weaver's architecture is designed to be highly extensible, allowing you to connect local AI agents to external creative suites, custom tools, and specialized workflows through the `IWeaverPlugin` interface.

## 1. The `IWeaverPlugin` Interface

All Weaver plugins must implement the `IWeaverPlugin` TypeScript interface. This contract ensures the plugin can be securely loaded, routed, and rendered by the Weaver OS shell without violating the zero-trust IPC boundary.

```typescript
export interface IWeaverPlugin {
  /**
   * A unique, machine-readable identifier for the plugin (e.g., 'ue5', 'blender').
   * Used for state management, routing, and IPC isolation.
   */
  namespace: string;

  /**
   * The human-readable display name of the plugin.
   */
  name: string;

  /**
   * A brief description of the plugin's capabilities.
   */
  description: string;

  /**
   * Optional version string (Semantic Versioning recommended).
   */
  version?: string;

  /**
   * Initialization lifecycle hook. 
   * Called when the plugin is first mounted by the WorkspaceManager.
   */
  onInit?: () => Promise<void>;

  /**
   * Cleanup lifecycle hook.
   * Called when the plugin is unmounted, switching contexts, or shutting down.
   */
  onDestroy?: () => Promise<void>;
}

## 2. Registering a Plugin

Plugins are managed by the global Zustand state (usePluginStore). When Weaver boots, it invokes the Native Rust Discovery Bridge to scan for installed plugins and loads their manifests.

To manually register a plugin during development:

Create your plugin implementation fulfilling IWeaverPlugin.

Add it to the initialization payload in usePluginStore.ts.

## 3. UI Routing & Context

When a user types \pi <namespace> in the Command Palette, Weaver updates the activePluginContext. The WorkspaceManager (located in src/App.tsx) listens to this context switch and dynamically replaces the standard IDE view with your plugin's custom React component bundle.

## 4. Security Constraints (Zero-Trust)

Weaver strictly enforces a zero-trust architecture between the frontend and the host OS.

No Direct Shell Access: Plugins must not attempt to spawn child processes or execute terminal commands directly from the React WebView.

Tauri IPC Only: All filesystem interactions, native OS dialogs, and executable spawns must be ferried through tightly scoped invoke() commands to the Rust backend (weaver-core).

Sandbox Compliance: If your plugin executes arbitrary code generated by an LLM, it must route that execution through the wasi_execute backend sandbox.
